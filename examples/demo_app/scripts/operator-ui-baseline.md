## Re-run & compare

Use this procedure to retake screenshots and verify they match this baseline:

1. Seed the demo database with the stress scenario:
   ```
   cd examples/demo_app && PARAPET_DEMO_SCENARIO=stress mix run priv/repo/seeds.exs
   ```
2. Start the demo app:
   ```
   cd examples/demo_app && mix phx.server
   ```
3. Capture screenshots into a temporary directory (PNGs land there — **never commit PNGs**):
   ```
   OUT=$(mktemp -d)
   bash examples/demo_app/scripts/capture_operator_ui_screenshots.sh "$OUT"
   ```
4. Compare each PNG against the rows above: verify the file exists, has the correct viewport and theme, and eyeball that the layout matches expectations.
5. To update the baseline after intentional UI changes, regenerate and commit only the Markdown:
   ```
   bash examples/demo_app/scripts/capture_operator_ui_screenshots.sh --manifest \
     > examples/demo_app/scripts/operator-ui-baseline.md
   # edit file to re-add the prose sections above and below the verbatim block, then:
   git add examples/demo_app/scripts/operator-ui-baseline.md
   git commit -m "chore: update operator UI screenshot baseline"
   ```
   Do **not** commit the PNGs from `$OUT`.

## CI manifest-drift check

CI runs the following command in the Postgres-free `quality` job to detect drift between the script and this committed baseline:

```bash
diff \
  <(bash examples/demo_app/scripts/capture_operator_ui_screenshots.sh --manifest) \
  <(sed -n '/^| name /,/^Total: /p' examples/demo_app/scripts/operator-ui-baseline.md)
```

A non-zero diff fails the build. To fix a failing drift check, re-run `--manifest`, update this file, and commit.
