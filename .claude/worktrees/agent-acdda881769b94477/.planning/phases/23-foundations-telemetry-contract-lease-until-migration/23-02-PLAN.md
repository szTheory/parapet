<objective>
Add the `lease_until` claim-lease column to `parapet_action_claims` and wire `ClaimService.claim_action/1` to default the column on insert AND self-heal expired claims atomically — irreversible-on-publish under the v1.0 freeze, so it lands before any capability dispatch code. This plan delivers FND-01 end-to-end: migration, schema field, ClaimService changes, concurrency_bootstrap DDL update, and the sequential concurrency test that proves self-heal works.

Purpose: today, if a node wins a claim (`insert_all on_conflict: :nothing` succeeds), then crashes before finishing the action, the row sits in `status='claimed'` forever — every subsequent `claim_action/1` call against that `(incident_id, action_kind, action_key)` returns `{:conflicted, claim}` regardless of how stale the claim is. `lease_until` + the in-place UPDATE-WHERE-lease_until<now() pattern closes that defect. This is the multi-node claim-leak pitfall (Pitfall 4 in PITFALLS.md).
Output: migration + schema + service + bootstrap DDL + test. Pure Postgres MVCC + Ecto — no new dependencies, no `mix.lock` churn.

Honors FND-01 + D-01 through D-08 from CONTEXT.md. Implements RESEARCH OQ-2 (self-heal lives inside `acquire_claim/2` — when `insert_all` returns 0, attempt `steal_expired_claim/2` BEFORE the existing `repo.one!` conflict path), OQ-3 (add `field(:lease_until, :utc_datetime_usec)` to the schema as a sub-task of FND-01), Finding #3 (`concurrency_bootstrap.ex` DDL must be updated), Finding #2 (`modify ... :from` option for reversibility), Pitfall 5 (`returning_fields/0` must include `:lease_until`), Pitfall 6 (`attrs` must include `:lease_until`).

`Parapet.Automation.ClaimService.claim_action/1` return contract (must remain stable; extended only with new metadata fields on the claim struct):

  - Argument: keyword list with `:incident_id`, `:action_kind`, `:action_key`, `:idempotency_key`, optional `:now`, optional `:attempt_count`.
  - Returns `{:won, claim}` on first-claim insert success OR on successful self-heal of an expired row.
  - Returns `{:conflicted, claim}` when a live (`lease_until >= now`) claim already exists for the same `(incident_id, action_kind, action_key)`.
  - Callers: `Parapet.Automation.Executor` (Oban auto-execution), `Parapet.Escalation.Worker` (escalation worker). Both pattern-match `{:won, _}` and `{:conflicted, _}` — return tuple shape MUST stay stable.

`Parapet.Spine.ActionClaim` schema invariants:

  - `@statuses ["claimed", "succeeded", "failed", "expired"]` — `"expired"` value remains UNUSED by this phase (per D-07; reserved for future archival work).
  - Unique constraint `(incident_id, action_kind, action_key)` enforced at the DB level (`action_claim.ex:75-77`). The self-heal UPDATE-in-place is the only safe steal mechanism — inserting a parallel row would violate this constraint and crash.
  - `timestamps(type: :utc_datetime_usec)` convention — `lease_until` matches this type for symmetry with `claimed_at`.

`ConcurrencyBootstrap.reset!/0` + `ConcurrencyRepo.insert/1` test scaffold:

  - `test/support/concurrency_bootstrap.ex` runs its own DDL inside `bootstrap!/0`; this is SEPARATE from Ecto migrations. The bootstrap CREATE TABLE for `parapet_action_claims` is the ground truth for what the concurrency test DB looks like — adding `lease_until` to the migration without adding it here means the concurrency test fails with `Postgrex.Error: column "lease_until" of relation "parapet_action_claims" does not exist` (Pitfall 1).
  - The bootstrap also creates indexes; the new partial index DDL string must be added to the list alongside the existing `parapet_action_claims_status_claimed_at_index` entry.

Migration reversibility contract (Ecto 3.x `def change`):

  - `add` of a column reverses to `remove`.
  - `execute("forward", "reverse")` runs `reverse` on rollback; empty string `""` marks the data migration as non-reversible (the structural rollback drops the column anyway, which removes the data).
  - `modify` requires the `:from` option to reverse — `modify :col, :type, null: false, from: {:type, null: true}` reverses to `modify :col, :type, null: true` (per Finding #2; without `:from`, `mix ecto.rollback` raises `cannot reverse migration command`).
