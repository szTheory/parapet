> (codebase exploration + external footgun research). This is the canonical research

## Goal

Parapet's six spine tables live in a dedicated, configurable `parapet` Postgres schema by
default; existing adopters get a documented, tested, **opt-in** upgrade path; `public`
remains a one-line opt-out. Closes the audited #1 quality weakness: no adopter-facing
DB-schema upgrade story (`docs/migration-v1.md` never mentions migrations/schema; only one
backfill test exists today).

## Key external finding (the central footgun)

**Ecto prefix precedence is asymmetric:**
- Writes: `repo opts > changeset prefix > @schema_prefix`
- Reads: `from/join prefix > @schema_prefix > repo opts`

A runtime `prefix:` repo option therefore creates a split-brain (writes and reads can resolve
to different schemas). **Decision: use a compile-time `@schema_prefix` only; ban runtime
`prefix:` repo options.** A shared macro stamps every spine schema, so the prefix
auto-propagates to queries, `Repo.insert`, `insert_all(SchemaModule, …)`, `Ecto.Multi` ops,
and joins (all joined schemas carry the same prefix).

**No connection `search_path`** — query-prefix approach only, so `public`-resident extensions
(`citext`, `uuid-ossp`, `pg_trgm`) keep resolving.

## Scope (concentrated — zero prefix awareness today; all tables resolve to `public`)

Lands in:
- **6 spine schemas** — `lib/parapet/spine/{incident,action_item,system_event,timeline_entry,tool_audit,action_claim}.ex`
- **2 generators** — `lib/mix/tasks/parapet.gen.spine.ex`, `parapet.gen.archive_indexes.ex` (+ `parapet.install.ex`)
- **5 library migrations** + **3 demo migrations**
- **Raw-SQL test infra** — `test/support/concurrency_bootstrap.ex` (CREATE SCHEMA + qualify CREATE TABLE/REFERENCES/TRUNCATE), `test/parapet/repo/migrations/add_lease_until_backfill_test.exs`
- **Cross-join / Multi / `insert_all` consistency points** — `lib/parapet/evidence.ex` (config chokepoint + Multi), `lib/parapet/automation/claim_service.ex` (`insert_all` write path), two cross-joins
- **Generator-output text tests** (expected churn) + docs

## Recommended approach

1. **Configurable compile-time prefix via a shared macro.** New `Parapet.Spine.Schema`:
   `use Ecto.Schema` + `@schema_prefix Application.compile_env(:parapet, :schema_prefix, "parapet")`.
   All 6 schemas switch `use Ecto.Schema` → `use Parapet.Spine.Schema`. `nil`/`"public"` ⇒ unprefixed.
2. **Single runtime resolution helper** colocated with `Parapet.Evidence.repo/0` (`lib/parapet/evidence.ex:22`):
   `schema_prefix/0` reading `Application.get_env(:parapet, :schema_prefix, "parapet")` for the
   runtime-needing sites (generators, raw SQL).
3. **Generators emit schema + prefix.** `parapet.gen.spine` (and `gen.archive_indexes` via `install`)
   write `config :parapet, :schema_prefix, "parapet"` and emit `execute "CREATE SCHEMA IF NOT EXISTS parapet"`
   (reversible; Oban-style `create_schema: false` escape hatch for least-privilege DBs) + `prefix:` on every
   `create table`/`references`/index. Prefix emitted as a literal so migrations stay self-contained.
4. **Raw-SQL test infra hand-qualified** (won't inherit `@schema_prefix`). Library's own 5 committed
   migrations + dev/test DB get the schema treatment.
5. **Existing-adopter upgrade = first-class deliverable.**
   - *Track A — stay on public:* `config :parapet, :schema_prefix, nil` + recompile (`mix deps.compile parapet --force`); tables untouched.
   - *Track B — move:* generated migration (`mix parapet.gen.schema_move`): `CREATE SCHEMA IF NOT EXISTS parapet`
     + `ALTER TABLE public.parapet_<t> SET SCHEMA parapet` for all 6 (metadata-only; carries indexes/constraints/sequences;
     FKs stay valid because all 6 move as a unit), reversible `down`. New installs default to `parapet`; **no forced migration on upgrade.**
6. **Demo app** updated end-to-end (config + 3 migrations) as the real-host smoke proof.
7. **Docs:** new `docs/upgrade-1.x.md` (default inversion, the `deps.compile --force` recompile requirement,
   Track A vs B copy-paste, least-privilege path, rollback); update `docs/deployment.md` + `README.md`.

## Rough phase shape (6 phases, continue numbering from Phase 51)

1. Prefix core + propagation + library migrations
2. Test infra green under prefix
3. Generators + fixtures
4. Upgrade path (Track A/B + tests)
5. Demo app + docs
6. Contract & release hardening

## Top risks / mitigations

- Runtime-`prefix:` split-brain → `@schema_prefix` only + test no prefix is threaded.
- `compile_env` recompile surprise → document `deps.compile --force`; optional `runtime.exs` divergence check.
- Least-privilege `CREATE SCHEMA` → `create_schema: false` hatch.
- Generator-output text-test churn → expected, owned by `GEN-MIGRATIONS`.
- Frozen telemetry/API → prefix is an internal DB detail; add the regression gate to done-criteria.

## Verification gates (the "did it actually work" criteria)

- Full suite green under `schema_prefix: "parapet"`.
- A **stay-on-public** test (`schema_prefix: nil` ⇒ unprefixed SQL, green queries).
- A **Track B upgrade round-trip** test (created in `public` → `SET SCHEMA` migration → resolves under `parapet`, FKs intact → `down` restores).
- The two cross-joins + `evidence.ex` Multi + `claim_service` `insert_all` exercised under prefix.
- Demo app boots, migrates into `parapet`, `--only smoke` lane passes end-to-end.
- `mix verify.public_api` + telemetry contract test still green.
- `docs/upgrade-1.x.md` steps manually walked once.

## Already-decided open items (noted for the executor)

- Min Ecto `~> 3.10` / modern PG floor unchanged (both support `@schema_prefix` and `ALTER … SET SCHEMA`).
