def register_recovery(id, attrs) when id in @valid_capabilities do
  Agent.update(__MODULE__, fn state ->
    capability = %{
      id: id,
      name: Keyword.fetch!(attrs, :name),
      target_kind: Keyword.get(attrs, :target_kind),
      preview: Keyword.get(attrs, :preview),
      execute: Keyword.get(attrs, :execute),
      preview_only: Keyword.get(attrs, :preview_only, false)
    }
    put_in(state, [:recovery, id], capability)
  end)
end

def attach(opts) when is_list(opts) do
  adapters = Keyword.get(opts, :adapters, [])
  Enum.each(adapters, fn adapter ->
    module_name = adapter |> to_string() |> Macro.camelize()
    module = Module.concat(Parapet.Integrations, module_name)
    if Code.ensure_loaded?(module) do
      apply(module, :setup, [])
    end
  end)
  {:ok, adapters}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host-app code → `Parapet.Recovery.attach/1` | Host application passes a list of its own modules to attach. No untrusted input — modules are statically declared in the host's own code. |
| `Parapet.Recovery.attach/1` → `Parapet.Capabilities` Agent | In-process function call to a supervised named Agent. No serialization boundary, no network. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01-01 | Spoofing | `attach/1` caller identity | accept | Host-app code calls `attach/1` from its own supervision tree at boot; there is no remote caller path. No authentication needed. |
| T-24-01-02 | Tampering | The 4 `@callback` signatures (id/0, label/0, preview/2, execute/2) | mitigate | Behaviour module declares the callbacks; Dialyzer surfaces missing/mis-named callbacks at compile time on the host module (per success criterion #1). Plan 03 adds runtime tests that exercise a fixture host module to confirm the dispatch contract. |
| T-24-01-03 | Repudiation | n/a — no audit emit in this plan | accept | Audit propagation lands in Phase 26 (AUD-01/02/03). Phase 24 ships the behaviour surface only; emit-site wiring is explicitly deferred per D-18. |
| T-24-01-04 | Information Disclosure | `module.id()` / `module.label()` strings stored in the registry | accept | `id()` is an atom from the allowlist (5 atoms total — Plan 02 adds the last 2). `label()` is a free-form String.t() supplied by the host app. The host owns its own labels; Parapet does not introspect or persist them outside the in-memory registry. |
| T-24-01-05 | Denial of Service | `attach/1` called with a huge list of modules | accept | `attach/1` runs once at host-app boot in the host's supervision tree. Even with 1000 modules, the per-module work (one `Code.ensure_loaded?` + at most one `Agent.update` write through the per-key `put_in`) is bounded in microseconds. Not an attack surface. |
| T-24-01-06 | Elevation of Privilege | `__using__/1` macro injection | mitigate | The macro injects ONLY `@behaviour Parapet.Recovery` (per D-02). No `alias`, no `import`, no helper functions. This is the most conservative ergonomic surface — adopters cannot accidentally inherit unintended functionality via `use`. The action criterion enforces this verbatim. |
| T-24-01-SC | Tampering (supply-chain) | npm/pip/cargo installs | accept | No new dependencies added in this plan (per D-22 / CONTEXT.md "Specific Ideas" bullet 7 — zero `mix.lock` churn). Pure-Elixir behaviour code. No package-install task in this plan. |
