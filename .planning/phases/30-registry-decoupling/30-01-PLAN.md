<task type="auto">
  <name>Task 1: Complete Test Isolation in Parapet.SLO.Registry</name>
  <files>lib/parapet/slo/registry.ex</files>
  <action>
Update the existing untracked/partially-implemented `Parapet.SLO.Registry` to prevent memory leaks and support `:providers`. Reference explicit analogs from `30-PATTERNS.md`:

Per **State Management Pattern**, ensure the GenServer starts and initializes an ETS table:
```elixir
  def init(:ok) do
    :ets.new(__MODULE__, [:set, :public, :named_table, read_concurrency: true])
    {:ok, %{}}
  end
```

Per **Test Isolation Pattern**, implement the `$callers` lookup to partition state per test process:
```elixir
  defp find_checkout_pid do
    pids = [self() | Process.get(:"$callers", [])]
    Enum.find(pids, fn pid ->
      case :ets.lookup(__MODULE__, {:checkout, pid}) do
        [{_, true}] -> true
        _ -> false
      end
    end)
  end
```

Specific changes to make:
1. In `handle_call({:checkout, pid})`, add `Process.monitor(pid)` to track test processes.
2. Add a `handle_info({:DOWN, _ref, :process, pid, _reason}, state)` callback. Inside it, use `:ets.match_delete(__MODULE__, {{:test, pid, :_}, :_})` and delete the checkout entry for `pid`. This prevents ETS leaks when tests finish or crash.
3. Per **Store/Provider Registration Pattern**, implement `register_providers(providers)` which uses `find_checkout_pid/0` to store the providers list in ETS under `{:test, pid, :providers}` (if test active) or `{:global, :providers}`.
4. Implement `providers/0` which queries ETS using the checkout pid for `{:test, pid, :providers}` or `{:global, :providers}`. If no result is found in ETS, fallback to `Application.get_env(:parapet, :providers, [])` (for runtime functionality).
  </action>
  <verify>
    <automated>grep -q "Process.monitor" lib/parapet/slo/registry.ex</automated>
  </verify>
  <done>Registry manages checkouts with process monitoring and allows storing/retrieving `:providers`.</done>
