# Phase 34 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 34 reframes the generated Operator UI around active response, action items, resolved history, and incident detail routes without changing stable `Parapet.Operator` API semantics, auth ownership, or generated install contents beyond the locked v1.3 roadmap scope.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix LiveView function components generated by `mix parapet.gen.ui`; no third-party component library |
| Icon library | none for this phase; use text labels and Phoenix link/button affordances |
| Font | host application sans-serif stack; generated UI must not import fonts |

Source: codebase scan found generated Phoenix LiveView templates in `priv/templates/parapet.gen.ui/` using Tailwind utility classes, with no `components.json`, shadcn preset, React/Vite app, or project Tailwind config in this library repository.

## Layout And Interaction Contract

| Area | Contract |
|------|----------|
| Primary route | `/parapet` is the active response landing route and must make the active incident queue, selected incident evidence, and action rail the first viewport experience. |
| Navigation | Generated router guidance exposes `Respond`, `Actions`, and `History` lanes as explicit top-level navigation. The active item uses `aria-current="page"`. |
| Detail routes | Preferred detail route is `/parapet/incidents/:id`; compatibility route `/parapet/:id` remains available. Both preserve the same evidence/action hierarchy. |
| Active response focal point | The focal point is the selected incident's impact, evidence timeline, and next safe action. The queue supports orientation, not visual dominance. |
| Mobile behavior | Queue and detail panes collapse into a single active pane; back navigation copy is `Back to active response`. |
| Refresh behavior | Queue changes are announced by a visible refresh panel with the primary action `Load latest changes`; do not silently reorder active queue context. |
| Motion | Use only targeted `transition-colors` or `transition-transform duration-100 ease-out active:scale-[0.96]`; avoid blanket transition utilities. |
| Touch targets | Navigation and action controls use at least 40px component height. This is a component dimension, not a spacing token. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, compact inline padding, badge internals |
| sm | 8px | Compact element spacing, badge gaps, small vertical rhythm |
| md | 16px | Default card padding, queue row padding, rail padding |
| lg | 24px | Detail section padding, page gutters on desktop |
| xl | 32px | Major layout gutters and constrained page padding |
| 2xl | 48px | Major section breaks only when vertical scrolling is available |
| 3xl | 64px | Page-level spacing; avoid inside dense operator work surfaces |

Exceptions: none.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.2 |
| Body | 14px | 400 | 1.5 |
| Heading | 18px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Use exactly these four sizes and two weights in generated Operator UI changes for this phase. Keep uppercase metadata labels at 12px with non-negative letter spacing only where existing generated templates already use the pattern for scan labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f5f4` | Page background, inactive workbench background, quiet overview bands |
| Secondary (30%) | `#ffffff` | Queue rows, detail surfaces, action rail cards, overview cards |
| Accent (10%) | `#0f766e` | Primary CTA, active nav item, focus ring, selected queue border, queue refresh action |
| Destructive | `#b91c1c` | Destructive actions only; not used for normal resolve, acknowledge, preview, or navigation states |

Accent reserved for: active nav item, primary CTA, focus ring, selected queue border, queue refresh action, and high-confidence success/evidence chips. Accent must not be applied to all links, all buttons, all cards, or decorative backgrounds.

Semantic status colors:

| Status | Contract |
|--------|----------|
| Warning / needs attention | Use amber surfaces and borders for escalation, warnings, and attention chips. |
| Neutral / history | Use stone surfaces and text for resolved history and non-urgent metadata. |
| Error / failed operation | Use destructive color only for failed or unsafe actions. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Load latest changes |
| Empty state heading | No active incidents |
| Empty state body | Open and investigating incidents will appear here. Use History to review resolved incidents without disrupting the active queue. |
| Error state | Recovery action could not proceed — refresh and review the timeline before trying again. |
| Destructive confirmation | No destructive actions in Phase 34. Mutating action labels must use specific verb+noun copy: `Acknowledge incident`, `Resolve incident`, `Preview mitigation`, `Confirm mitigation`, `Trigger next escalation`, `Suppress escalation`. Confirmation remains through existing preview/confirm and audit-payload flows; do not add generic one-word or unlabeled destructive controls. |

Additional route and navigation copy:

| Context | Copy |
|---------|------|
| Header eyebrow | Parapet Operator |
| Header title | Active response workbench |
| Top nav items | Respond, Actions, History |
| Queue heading | Incident Queue |
| Action lane heading | Pending action items |
| Detail back link | Back to active response |
| Compatibility note for generated route guidance | Mount both `/parapet/incidents/:id` and `/parapet/:id`; prefer `/parapet/incidents/:id` in generated links. |
