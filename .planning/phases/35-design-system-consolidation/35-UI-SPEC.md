# Phase 35 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 35 consolidates the generated Operator UI design system so repeated Tailwind treatments become shared Phoenix LiveView function-component helpers with consistent affordances. This phase must not change stable `Parapet.Operator` API semantics, auth ownership, default dependency surface, or the generated route IA established in Phase 34.

Assumption: Phase 35 has no dedicated `CONTEXT.md` or `RESEARCH.md` yet. Low-impact design details are auto-decided from the active v1.3 requirements, Phase 34 UI-SPEC, and the existing generated templates in `priv/templates/parapet.gen.ui/`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix LiveView function components generated by `mix parapet.gen.ui`; no third-party component library |
| Icon library | none for this phase; keep generated controls text-first and do not add icon dependencies |
| Font | host application sans-serif stack; generated UI must not import fonts |

Source: the generated Operator UI currently lives in `priv/templates/parapet.gen.ui/operator_components.ex.eex`, `operator_live.ex.eex`, and `operator_detail_live.ex.eex`, using Tailwind utilities and Phoenix links/buttons. There is no shadcn setup, React app, project Tailwind token file, or third-party UI registry in this repository.

## Component Consolidation Contract

Phase 35 implementation should consolidate repeated styling into local generated helpers. The goal is to reduce visual drift while preserving the generated static-template model.

| Surface | Contract |
|---------|----------|
| Navigation | Keep `operator_nav/1` and `nav_item/1` as the only top-level nav pattern. Active item uses `aria-current="page"`, teal active treatment, and visible focus ring. |
| Overview cards | Queue count, pending actions, and critical journeys share one overview-card surface: white background, 12px label, 24px tabular value, 16px padding, 12px radius, `shadow-sm`, and `ring-1 ring-stone-900/5`. |
| Queue rows | Queue rows share selected, hover, focus, and disabled affordance helpers. Selected rows use a teal left border and quiet teal background; unselected rows stay white with stone hover. |
| Status chips | Incident state, severity, attention, journey, escalation, execution, and external-evidence chips use one chip helper family with 12px text, pill radius, semantic color pair, and ring/border when the chip communicates state. |
| Action rail cards | Acknowledge, escalation controls, resolve, action item cards, and preview/confirm cards share one action-card surface and must show audit/risk copy before the mutating control. |
| Timeline rows | Timeline entries keep compact evidence-first hierarchy: event title, body/evidence, source chip, and timestamp. Do not introduce decorative cards around every timeline row. |
| Empty states | Queue and action empty states share dashed or quiet surface treatments and action-oriented copy. Empty states must not be marketing-style panels. |
| Touch targets | All generated links and buttons used as controls keep `min-h-[40px]`; primary mutating controls should fill their card width where currently full-width. |

Do not extract a standalone design-system package or introduce runtime configuration in Phase 35. Helpers stay inside the generated Operator component template so adopters receive deterministic generated code.

## Interaction And Motion Contract

| Interaction | Contract |
|-------------|----------|
| Focus | Interactive generated controls use visible `focus:outline-none focus:ring-2` with teal for primary navigation/actions and semantic amber/red only when the control itself is amber/red. |
| Hover | Hover states may adjust background/text color only. They must not resize rows, cards, chips, or layout containers. |
| Active press | Buttons may use `transition-transform duration-100 ease-out active:scale-[0.96]` only for explicit buttons and primary action links. Do not apply press scaling to rows, cards, timeline entries, or layout containers. |
| Page refresh | Keep Phase 34's explicit refresh panel and `Load latest changes` action. Do not silently reorder active queue context. |
| Reduced motion | Any new transition class must be non-essential and safe when motion is reduced. Avoid animations, spinners, pulsing highlights, and `transition-all`. |
| Selection | Queue row selection remains visible through both `aria-current` and a visual selected state. Navigation selection remains `aria-current="page"`. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline chip gaps, compact icon-free control gaps, metadata nudges |
| sm | 8px | Chip padding, row internal gaps, compact card rhythm |
| md | 16px | Default card padding, queue row padding, rail padding, mobile section padding |
| lg | 24px | Detail section padding, desktop card groups, modal/preview body padding |
| xl | 32px | Main content gutters and large grid gaps |
| 2xl | 48px | Major vertical separation only outside dense work surfaces |
| 3xl | 64px | Reserved for page-level spacing; avoid in Operator workbench panels |

Exceptions: `min-h-[40px]` is allowed for control touch targets because it is a component dimension, not a spacing token. `text-[10px]` may remain only for dense audit metadata, small execution badges, and preview technical labels that already need compact scanning.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata label | 12px | 600 | 1.2 |
| Body | 14px | 400 | 1.5 |
| Emphasized body | 14px | 600 | 1.4 |
| Heading | 18px | 600 | 1.25 |
| Display value | 24px | 600 | 1.2 |

Use these generated UI roles consistently. Keep tabular numbers for counts, IDs, timestamps, and affected counts. Avoid `font-bold` except for very small technical labels where the existing generated preview/audit pattern needs density; prefer `font-semibold` for headings and controls.

Uppercase metadata labels may use non-negative letter spacing no tighter than the current `tracking-[0.16em]`/`tracking-wide` pattern. Do not add negative letter spacing.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f5f4` | Page background, inactive workbench background, quiet overview bands |
| Secondary (30%) | `#ffffff` | Queue rows, detail surfaces, action rail cards, overview cards |
| Accent (10%) | `#0f766e` | Primary CTA, active nav item, focus ring, selected queue border, queue refresh action |
| Destructive | `#b91c1c` | Failed or unsafe action states only; not for normal resolve, acknowledge, preview, or navigation |

Accent reserved for: active nav item, primary CTA, focus ring, selected queue border, queue refresh action, and high-confidence evidence/success chips. Accent must not be applied to all links, all buttons, all cards, or decorative backgrounds.

Semantic color contract:

| Semantic Role | Tailwind Family | Usage |
|---------------|-----------------|-------|
| Neutral | stone | Page, surfaces, borders, history, inactive metadata |
| Primary / evidence | teal | Selected nav/queue, queue refresh, evidence-first chips |
| Warning / attention | amber | Escalation, warnings, attention chips, suppression controls |
| Success / complete | emerald | Resolved, executed, healthy, successful audit outcome |
| Info / external evidence | blue | External references and informational evidence only |
| Recovery preview | indigo | Preview/confirm surfaces already using recovery-preview treatment |
| Impact summary | violet | Existing impact summary surface only; do not expand violet into primary actions |
| Error / unsafe | red | Failed operation, warning lists with risk, destructive/unsafe states |

Phase 35 should reduce arbitrary color drift by routing chips and action states through named helpers. It may retain the existing indigo/violet/blue treatments where they have specific meaning, but should not expand them into a one-note palette or use them as generic decoration.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Load latest changes |
| Empty state heading | No active incidents |
| Empty state body | Open and investigating incidents will appear here. Use History to review resolved incidents without disrupting the active queue. |
| Action center empty heading | No pending action items |
| Action center empty body | Recovery work appears here when an incident has a concrete item to inspect or resolve. |
| Error state | Recovery action could not proceed - refresh and review the timeline before trying again. |
| Destructive confirmation | No destructive actions in Phase 35. Mutating controls must use specific verb+noun labels and adjacent audit/risk copy before execution. |

Action and audit copy requirements:

| Control | Required Pre-Click Message |
|---------|----------------------------|
| Acknowledge incident | Take ownership of this incident. Writes a durable audit record and timeline entry. |
| Resolve incident | Mark incident as resolved only after user impact has stopped and evidence is complete. Writes audit record. |
| Preview mitigation | Preview scoped changes before execution. No recovery action runs until confirm. |
| Confirm mitigation | Execute bounded recovery. Writes a durable audit record with actor, reason, correlation id, and outcome. |
| Trigger next escalation | Request the next escalation only after reviewing current status and the canonical timeline. Every request is audited. |
| Suppress escalation | Suppress pending escalation for the displayed bounded window. Every request is audited. |
| External action item | Review the linked incident evidence before recovery. Capability confirms write audit records. |

Copy must stay active-response oriented: impact, evidence, next safe action, audit, and recovery. Avoid generic labels like `Submit`, `Go`, `Run`, `Open`, or `OK` when a safer verb+noun label is available.
