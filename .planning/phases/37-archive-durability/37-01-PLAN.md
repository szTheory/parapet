<objective>
Replace the current direct JSONL append/delete archive flow with a staged local export that preserves the complete Parapet-owned evidence bundle, verifies the artifact before prune, deletes only exact selected incident ids, and returns structured `Summary` or `Failure` tuples.

Purpose: ARCH-01 through ARCH-04 require the archive path to be an honest evidence lifecycle boundary, not a best-effort append followed by destructive delete. This plan owns the core library behavior only; caller surfaces are handled in Plan 02.

Output: `Parapet.Evidence.Archiver.archive/3` returns `{:ok, %Parapet.Evidence.Archiver.Summary{}}` or `{:error, %Parapet.Evidence.Archiver.Failure{}}`, writes verified archive/manifest artifacts, and has focused tests for complete bundles, retention boundaries, and partial failures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB evidence -> archive artifact | Complete Parapet-owned incident evidence must survive before deletion |
| Archive artifact -> prune | Destructive deletion must depend on verified export, not best-effort writes |
| Failure value -> operator action | Returned failures must be enough to decide rerun/inspect/escalate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-01 | Tampering | cutoff selection/delete selection drift | mitigate | Materialize selected ids once and delete only those ids. |
| T-37-02 | Information Disclosure | external provider/host data in archive | accept boundary | Archive only Parapet-owned schemas listed in D-05 and preserve external references already stored in payloads. |
| T-37-03 | Repudiation | partial write followed by delete | mitigate | Stage, verify, publish, and manifest before prune. |
| T-37-04 | Repudiation | delete failure hidden by success tuple | mitigate | Return `Failure{stage: :delete_records}` with partial summary. |
</threat_model>
