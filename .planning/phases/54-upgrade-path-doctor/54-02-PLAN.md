<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adopter `--schema` flag → generated SQL | the schema name is interpolated into `CREATE SCHEMA` / `ALTER … SET SCHEMA` heredocs |
| six spine table names → abort-guard SQL | fixed literal ARRAY interpolated into a DO-block |
| generated migration → adopter prod DB | the emitted `down` could destroy the schema if it dropped it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-54-04 | Tampering | `--schema` value in CREATE SCHEMA / ALTER … SET SCHEMA | high | mitigate | `resolve_prefix` → `normalize/1` → `safe_ident!/1` allowlist (`^[a-z_][a-z0-9_]*$`, ≤63 bytes) runs BEFORE the value reaches any heredoc (inherited via resolve_prefix; the move task cannot bypass it) (D-06). |
| T-54-05 | Tampering | table name in the migrate-time abort guard | medium | mitigate | `quote_ident(t)` inside the DO-block; the table list is a FIXED literal ARRAY, never user input (D-10). |
| T-54-06 | Denial of Service / data loss | destructive rollback | high | mitigate | `down` NEVER `DROP SCHEMA` (fail-closed, D-08) — asserted by the golden test's negative grep. |
| T-54-07 | Denial of Service | prod lock-queue pile-up during the move | low | mitigate | `after_begin` sets `SET LOCAL lock_timeout '5s'` so a blocked `SET SCHEMA` fails fast instead of queuing prod traffic behind the FIFO lock queue (D-08). |
</threat_model>
