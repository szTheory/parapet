  <behavior>
    - resolve_prefix(nil, nil) → {:ok, "parapet"} (default; D-06 precedence tail).
    - resolve_prefix("custom", nil) → {:ok, "custom"} (flag only).
    - resolve_prefix(nil, "custom") → {:ok, "custom"} (existing config only).
    - resolve_prefix("parapet", "parapet") → {:ok, "parapet"} (agreement).
    - resolve_prefix("public", nil) → {:ok, nil} (normalize maps "public"/""/nil → nil; nil/legacy leg).
    - resolve_prefix("alpha", "beta") → {:conflict, "alpha", "beta"} (flag wins downstream, tuple signals the warn path; NO raise).
    - resolve_prefix("Bad-Name", nil) → raises ArgumentError (safe_ident! rejection via normalize; a distinct failure mode from :conflict).
  </behavior>
  <action>
    Implement `resolve_prefix/2` as a pure function on `Parapet.Spine.Schema` per D-05: normalize both the flag and the existing-config argument through the existing `normalize/1` (which already funnels to `safe_ident!/1` — do NOT call `safe_ident!` separately), then apply precedence `flag > existing config > default "parapet"` (D-06) via a `cond`. When both normalized values are non-nil and differ, return `{:conflict, normalized_flag, normalized_config}` — flag wins for the run but the tuple signals the caller to warn (never clobber, never crash). When both are absent, return `{:ok, normalize("parapet")}` so the default itself is allowlist-checked and normalized. Reuse the single `@default_prefix`-equivalent literal by calling `normalize("parapet")`; do NOT introduce a second default literal (D-00). Add `resolve_prefix/1` — the Igniter arity — that extracts `igniter.args.options[:schema]` and `Application.get_env(:parapet, :schema_prefix)` and delegates to the pure core (per Open Question #1, this arity may thread the igniter for a later warning; return shape is Claude's discretion — recommend leaving the actual `add_warning` call to the calling task so this arity stays a thin reader). Add a `@doc` on `resolve_prefix` naming it the generate-time reader and stating it must never call `__prefix__/0` or read `@prefix` (the D-09 firewall); the compile-time `__prefix__/0` @doc already carries its half of the pair. Do NOT let `resolve_prefix` reference `@prefix` or `__prefix__/0` anywhere.
  </action>
