> shell (header / nav / tabs / theme switcher / cockpit header) and all data-display

### NAV-02 — 390px responsive shell

The `operator_nav` shell must render without horizontal overflow at 390px viewport.

**Current structure:** `flex flex-col gap-3 px-4 py-3 md:flex-row md:items-center md:justify-between md:px-6`

**Contract:**
- Mobile (< md, 390px): `flex-col` stacking is already present. Three nav items use `flex-wrap gap-2` — this is correct and must be preserved.
- The three nav items ("Respond", "Actions", "History") must each fit on one line at 390px with their label text. At 390px the three items can share one row using `flex-wrap` — they must not overlap or overflow.
- Theme switcher (`theme_control`) at 390px: must stack below the nav row, not force horizontal overflow. The current `flex flex-col gap-3` on the header container handles this — verify the theme control does not min-width exceed 390px minus 2×padding (= 390 - 32 = 358px available).
- **Hard rule:** `overflow-x: hidden` on the `.parapet-ui` wrapper is NOT the fix. The shell items themselves must not require more than 390px total width at any breakpoint. Each nav item uses `min-h-[40px] rounded-lg px-3 py-2 text-sm` — at 390px the three items fit as `flex-wrap gap-2` without overflow.
- No horizontal scrollbar at 390px. If the nav items cannot fit in a single row, they wrap — this is correct behavior.

## Data Display Contract (DATA-01..06)

### DATA-01 — Deliberate truncation and wrapping

**Incident row (`incident_row/1`):**

The row uses `min-w-0 flex-1` on the text column and `shrink-0` on the timestamp column.
This is correct — `min-w-0` allows text to truncate inside flex.

| Field | Behavior | Implementation |
|-------|----------|----------------|
| `incident.title` | Single line, truncate at container edge | `truncate text-sm font-semibold` — already present, preserve |
| `incident.secondary_line` | Single line, truncate | `truncate text-sm` — already present, preserve |
| Chip row (state, severity, attention) | Wrap (`flex-wrap`) — chips never truncate, they wrap to next line | `flex flex-wrap items-center gap-2` — already present, preserve |
| Timestamp label | Never truncate — `shrink-0` column | `shrink-0 text-right` — already present, preserve |
| Incident ID (monospace) | `break-all` to prevent horizontal overflow | `break-all tabular-nums font-mono` — already present in `incident_summary`, preserve |

**Incident queue list column layout:**
- Queue column width: `minmax(0, 22rem)` — this is a max, not a min. At narrow viewports the column shrinks. The `min-w-0` inside each row ensures text truncates, not overflows.
- At 390px: the two-column `grid gap-6 lg:grid-cols-[minmax(0,22rem)_minmax(0,1fr)]` collapses to single column (no `md:` breakpoint on this grid — it is `lg:`). Confirm the grid is `grid gap-6` (single column) until `lg` breakpoint. At 390px it renders as a stacked single-column layout — this is correct.

**Timeline entry (`incident_timeline/1`):**

| Field | Behavior | Implementation |
|-------|----------|----------------|
| Entry title | Wrap (`whitespace-normal break-words`) | Currently `text-sm font-medium text-stone-900` — add `min-w-0` to the parent `<div>` containing the title + actor chip |
| Entry body (evidence text, URLs) | Wrap with `break-words`; URLs use `break-all` | External links already have `break-all` — preserve. Body text: add `break-words` if not present |
| Actor chip | Never truncate — chips wrap alongside title | `flex items-center gap-2 flex-wrap` — already present, preserve |
| Timestamp | `whitespace-nowrap text-right` — already correct | Do not change |
| Badge letter (SYS/OP/AI/EXT/EV) | Always 2 chars max, centered in 32×32 circle | `h-8 w-8 text-[11px] font-semibold` — already present. No overflow possible |

**Tables / evidence panels (operator_detail_live, escalation chain):**

The escalation chain renders as a `<dl>` grid. No `<table>` element is used in the current
templates. The `<dl>` grid uses `grid-cols-1 sm:grid-cols-2 gap-3` — responsive and safe.

**Rule:** No `<table>` element in the templates requires `table-layout: fixed` or explicit
column widths. If a table is added in future, specify `table-fixed` + `w-full` + per-column
`w-[N%]` constraints. Phase 46 does not add new table elements.

**Long string handling in summary (`incident_summary/1`):**

The h1 in `incident_summary` uses `max-w-xs whitespace-normal break-words` on mobile and
`sm:max-w-none sm:text-balance`. This is correct — Phase 46 preserves it and adds `min-w-0`
to the parent `div.min-w-0.overflow-hidden` if not already present (it is — preserve).

### DATA-02 — Internal scroll correctness

**Page-level scroll:** `.parapet-ui` uses `flex min-h-screen flex-col`. The page scrolls as
a whole — this is correct and must not be changed.

**Internal scroll regions that exist:**

| Region | Current behavior | Required contract |
|--------|-----------------|-------------------|
| Incident list (queue) | No explicit scroll region — list grows, page scrolls | CORRECT — do not add `overflow-y-auto` to the queue column |
| Timeline (inside cockpit) | No explicit scroll — timeline grows within the cockpit section | CORRECT — do not add internal scroll to timeline |
| Preview panel | Rendered as a side card, no scroll | CORRECT |
| Aside (action rail, detail page) | No internal scroll | CORRECT |

**Rule:** Phase 46 adds NO new `overflow-y-auto` or `overflow-y-scroll` regions. The only
acceptable internal scroll region is a modal/drawer (Phase 47 scope). Every surface in Phase
46 scope uses natural document flow + page-level scroll.

**Anti-pattern to avoid:** `overflow-hidden` on any container that wraps variable-length
text content (incident titles, timeline entries). The only `overflow-hidden` in Phase 46
scope is on `incident_summary`'s outer `div.min-w-0.overflow-hidden` — which is correct
because the `min-w-0` + `break-words` prevents actual overflow while `overflow-hidden`
clips background paint artifacts. Preserve this pattern; do not apply it to new containers.

### DATA-03 — Timeline degradation (zero/few/many entries)

**Zero entries:**

```heex
<div class="flex min-h-[12rem] items-center justify-center text-center px-4 py-8">
  <div>
    <!-- icon: clock or empty list — inline SVG, aria-hidden="true", h-8 w-8 text-[color:var(--parapet-text-muted)] -->
    <svg aria-hidden="true" class="mx-auto h-8 w-8 mb-3" .../>
    <p class="text-sm font-semibold" style="color: var(--parapet-text);">No timeline entries yet</p>
    <p class="mt-1 text-sm" style="color: var(--parapet-text-muted);">Evidence and operator actions will appear here as they are recorded.</p>
  </div>
</div>
```

**Few entries (1–3):** Render normally. The connector spine (`h-full w-0.5`) on the last
entry must not show — use `-mb-8` on `<ul>` and `pb-8` on the last `<li>` to clip the
spine on the final entry. **Phase 46 adds a CSS rule or conditional class to suppress the
connector line on the last timeline item:**

```css
/* Hide spine on last timeline entry */
.parapet-ui .po-timeline-list li:last-child > div > span[aria-hidden="true"] {
  display: none;
}
```

Or apply `last:hidden` Tailwind class to the spine `<span>` if Tailwind JIT is available.

**Many entries (20+):** No pagination is added in Phase 46. The timeline renders all
entries as a vertically-scrolling list inside the page scroll. No virtual scrolling or
truncation. The only protection is `break-words` on entry text fields.

**Bounded fields:** Timestamps are formatted (`readable_datetime/1`) — no raw ISO strings
appear in the visible UI. Badge letters are max 3 chars (SYS/OP/AI/EXT/EV). Actor chip
text maps from `timeline_actor_copy/1` — these are short domain terms.

### DATA-06 — Loading/skeleton states (reduced-motion-safe, no layout jump)

**Skeleton anatomy:**

A skeleton placeholder replaces live content during data load. For Phase 46 scope (incident
list, timeline), use this pattern:

```heex
<div class="animate-pulse space-y-3" aria-hidden="true" aria-label="Loading incidents">
  <!-- Each placeholder block matches the HEIGHT of the content it replaces -->
  <div class="h-16 rounded-lg bg-[color:var(--parapet-panel-muted)]"></div>
  <div class="h-16 rounded-lg bg-[color:var(--parapet-panel-muted)]"></div>
  <div class="h-16 rounded-lg bg-[color:var(--parapet-panel-muted)]"></div>
</div>
```

**Reduced-motion:** `animate-pulse` uses a CSS animation that is zeroed by the existing
`prefers-reduced-motion` block in `operator_theme_bootstrap/1`:
```css
@media (prefers-reduced-motion: reduce) {
  .parapet-ui * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```
Under reduced-motion, skeleton blocks render as static flat fills — no animation. This is correct.

**No layout jump rule:** Each skeleton block must match the height of the content it
replaces BEFORE the content loads. Incident rows are approximately `h-16` (64px). Timeline
entries are approximately `h-20` (80px including the connector space). Use these fixed
heights on skeleton blocks so the layout does not reflow when content arrives.

**`aria-hidden="true"`** on the skeleton container — it is decorative. A visible loading
status must also be available to screen readers; add `aria-live="polite"` + `aria-busy="true"`
on the container that hosts either the skeleton OR the real content (not both).

**Pattern:**
```heex
<div aria-live="polite" aria-busy={if @loading?, do: "true", else: "false"}>
  <%= if @loading? do %>
    <div class="animate-pulse ..." aria-hidden="true">...</div>
  <% else %>
    <.incident_list ... />
  <% end %>
</div>
```

**Note:** The current templates do not have explicit loading states — they rely on Phoenix
LiveView's mount/handle_params phasing. Phase 46 does NOT require adding a loading spinner
or skeleton to every surface. It defines the PATTERN for where loading states ARE added
(specifically the incident queue list). If no loading state exists for a surface, the surface
simply renders the empty state or the content — no intermediate skeleton is required. Skeletons
are only added where the UX would otherwise show a jarring blank-then-populated flash.

### A11Y-03 — Every interactive element keyboard-reachable

**Interactive elements in Phase 46 scope:**

| Element | Keyboard reachable? | Focus indicator | Notes |
|---------|--------------------|--------------|----|
| Skip-to-content link | YES — first in tab order | `po-focus` ring | New in Phase 46 |
| Nav items (Respond/Actions/History) | YES | `po-focus` ring | Already wired |
| Theme switcher buttons | YES | `po-focus` ring | Already wired |
| Queue row links (`<.link patch=...>`) | YES | `po-focus` ring | Already wired |
| Pagination links (Previous/Next/Newer/Older) | YES | `po-focus` ring via `pagination_link_class` | Verify po-focus is included |
| Queue-refresh button | YES | `po-focus` ring | Already wired (Phase 45) |
| Back-navigation link in detail header | YES | `po-focus` ring | Already uses `po-link` which carries `po-focus` |
| External links in timeline/evidence | YES | `po-focus` ring via `po-link` | Already wired |
| Timeline entries | Not interactive — list items are not focusable | n/a | Correct |
| Empty state containers | Not interactive | n/a | Correct — no focus needed |

**Pagination link keyboard contract:**
The `pagination_link_class/1` function must include `po-focus` in the returned classes for
enabled pagination links. Currently it returns styling classes; Phase 46 ensures `po-focus`
is included.

Disabled pagination links must not be focusable. Use `aria-disabled="true"` + `tabindex="-1"`
on disabled `<.link>` pagination elements (not the `disabled` HTML attribute, which is for
buttons only).

### A11Y-04 — Tab order logical, no keyboard traps

**Tab order on the response page (`:response` mode):**

1. Skip-to-content link (first, visually hidden until focused)
2. Nav items: Respond → Actions → History
3. Theme switcher: Light → Dark → System
4. Queue row links (in DOM order, top to bottom)
5. Pagination: Previous → Next
6. Queue-refresh button (if visible)
7. Back-navigation and breadcrumb links (if in cockpit)
8. External links in timeline (in DOM order)
9. Action rail buttons (if visible)

**No keyboard traps:** No modal/drawer/overlay is in Phase 46 scope. There are no focus
traps to implement or avoid. (Focus trap for modals is Phase 47 scope — GROUP-05.)

**`<.link navigate=...>` and `<.link patch=...>`** — Phoenix LiveView link components
render as `<a>` elements with `href`. They are naturally in tab order. No special treatment
needed beyond the `po-focus` class.

**`tabindex` rules for Phase 46:**
- Do NOT add positive `tabindex` values to any element. Use DOM order.
- Add `tabindex="-1"` only to disabled pagination links (as above).
- The skip-to-content link target `<main id="parapet-main">` may optionally receive `tabindex="-1"` to ensure focus moves to it when the skip link is activated (programmatic focus): `<main id="parapet-main" tabindex="-1">`. This is safe and correct.
