## Overview

The v1.0 milestone was Parapet's credibility/commitment release. Posture: freeze the public API and telemetry contract under a written stability + deprecation policy, close the OSS-governance and integration-docs gaps that block adopter trust, ship a runnable demo Phoenix app as a live CI contract test, and cut `1.0.0` honestly through Release Please. No new runtime feature surface — the Oban-1.0 model. Research backing lived in `.planning/research/V1-*.md` and `.planning/research/V1-SLO-WIZARD-BUNDLES.md`.

## Milestone Goal

Freeze Parapet's public API and telemetry contract under a written stability + deprecation policy, ship the release-readiness scaffolding that lets a stranger trust `~> 1.0`, and cut `1.0.0`.

## Milestone Summary

**Key Decisions:**

- **Freeze depth = stability tiers + deprecation policy, not a full hardening pass.** Proportionate verify gate (REL-03) used instead of a security/performance audit (D-19 — Oban-1.0 model).
- **No `CODE_OF_CONDUCT.md`** (GOV-03 intentionally omitted per user decision — content-filter issue; not considered necessary for v1.0 credibility).
- **Provider-as-bundle, not a separate `Parapet.SLO.Bundle` abstraction.** A `Parapet.SLO.Provider` returning multiple slices already _is_ the bundle (`DeliverySaaS` proves it). Macro saving ~5 lines would freeze a premature abstraction.
- **Demo app is examples-path, not in Hex.** `examples/demo_app/` is a path-dep Phoenix app excluded from the published package and wired into `release_gate` as a required CI check — turns the frozen surface into a live contract test.
- **Release-Please choreography for `0.10.0 → 1.0.0`** rather than hand-editing the manifest — the `release-as` pin is the one-time steering, then removed post-cut along with both pre-major bump flags.
- **Flag-based Igniter tasks, not interactive wizards** — Igniter has no interactive-prompt API; prompt-driven `Mix.Task` loses dry-run/composability. Codified for SLO-W1 (re-targeted to v1.2).
- **Solo OSS posture: required approving reviews = 0, `release_gate` is the real safety net.** Do not recommend re-enabling required reviews without a co-maintainer (see `MEMORY/solo-oss-required-reviews-disabled`).

**Issues Resolved:**

- Phase 21 CR-01 (History-tab KeyError on resolved incidents) — closed in plan 21-05 / commit `551ef05` before v1.0.0.
- Phase 21 CR-02 (LiveView JS pipeline missing — esbuild + `assets/js/app.js` + `<script defer>` tag) — code shipped in plan 21-05 but the JS pipeline wiring fix landed post-v1.0.0 as v1.0.1 (commit `885e7d7`).
- v1.0.1 → v1.0.2 → v1.0.3 hardened the auto-publish chain (Release Please PR auto-merge, `workflow_dispatch` step, `actions:write` permission, PAT-validated end-to-end chain).
- `parapet.gen.grafana_test` global-SLO-state leakage repaired in `fa26ac2` (v1.0.2 train). Graduation candidate: move `Parapet.SLO` registry off `Application` env in v1.2 — thread: `.planning/threads/slo-state-off-application-env.md`.

**Issues Deferred:**

- **GOV-03** `CODE_OF_CONDUCT.md` — intentional decision, not a gap. Stays deferred.
- **SLO state on `Application` env** — bandaged in v1.0.1 (`fa26ac2`), graduates to off-Application-env in v1.2 before SLO-W1.
- **Branch-protection enforcement** — `release_gate` is the required check, but `enforce_admins=true` enforcement and the full conventional-commit taxonomy + PR template work moves to v1.2 (per `.planning/threads/release-gate-enforcement.md`).
- **Strategic v1.1+ scope** — v1.1 became Actionable Recovery (per 2026-05-27 strategic assessment, `.planning/NEXT-STEP-ASSESSMENT.md`). SLO-W1, CI matrix, supply-chain hardening, missing-guides work re-targeted to v1.2.

**Technical Debt Incurred:**

- Plan `22-04-SUMMARY.md` was not written — Task 2 was a `checkpoint:human-verify` blocking gate that was satisfied externally by the actual v1.0.0 cut (visible via `git tag v1.0.0`). Completion evidence is the live release, not a summary file. Recorded honestly here.
- Phase 21 `21-VERIFICATION.md` shows `status: gaps_found` but the gaps it enumerates (CR-01, CR-02, branch-protection wiring) were all closed by 21-05/21-06 and v1.0.1. The verification file itself was not re-run; the closure is documented in the SUMMARY files and the actual shipped point releases.
- No `v1.0-MILESTONE-AUDIT.md` was ever generated (the `/gsd:audit-milestone` step was skipped). This is documented under "Known Gaps" in the MILESTONES.md entry.
