## Idempotence Proof

The milestone is forward-only and idempotent by three complementary mechanisms:

**1. `mix parapet.gen.ui --dry-run` honors Igniter's super/1:**
`lib/mix/tasks/parapet.gen.ui.ex:74` — the font copy is guarded by `unless "--dry-run" in argv`. Igniter's `super/1` (invoked at line 70) internally respects `--dry-run` across all `copy_template` calls. On an already-installed host where all three target files exist, `--dry-run` makes zero file changes. Note: running `--dry-run` on the Parapet repo itself (no host) surfaces an interactive Igniter prompt in non-TTY context; the proof is the code path at parapet.gen.ui.ex:74 + `Igniter.do_or_dry_run/2`.

**2. Three `on_exists: :skip` call sites:**
- `parapet.gen.ui.ex:43` — operator_live.ex
- `parapet.gen.ui.ex:54` — operator_detail_live.ex
- `parapet.gen.ui.ex:65` — operator_components.ex

Generated host markup is never overwritten or destructively edited. Re-running `mix parapet.gen.ui` on an already-installed host skips all three files. This is the Ecto-generator / Terraform-plan "forward-only" property: safe to re-run.

**3. Audit-matrix ledger semantics:**
`brandbook/notes/operator-audit-matrix.md` cells advance `todo → done → verified` only. Re-runs of the audit revisit only non-`verified` or regressed cells. As of this milestone close, every component row is at `verified` or documented `N/A-by-design`. The ledger does not regress.
